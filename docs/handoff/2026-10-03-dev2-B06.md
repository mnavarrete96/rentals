## Decisiones tomadas y por qué

### D-1: Sin bloqueo por intentos fallidos (failedAttempts/lockedUntil)
ARCHITECTURE §13 clasifica D-6 (bloqueo por intentos) como "abierta, YAGNI si WAF rate-based". La tarea describía un contador, pero no hay un ADR que lo apruebe. AppUser no tiene failedAttempts. Si el usuario decide activarlo, requiere ADR + V3__auth_add_lockout.sql. Se reporta al líder.

### D-2: GlobalExceptionHandler creado en B-06 (no en B-04)
Necesario para que BadCredentialsException del AuthController retorne 401 ProblemDetail (sin handler, Spring lanza ServletException y falla el test). B-04 extiende este handler con TenantNotFoundException, etc.

### D-3: Spring Boot 4.x — Jackson 3.x usa tools.jackson
En Spring Boot 4.x, Jackson 3.x reemplazó `com.fasterxml.jackson` por `tools.jackson`. Los tests no deben importar `com.fasterxml.jackson.databind.ObjectMapper`.

### D-4: Spring Boot 4.x — @MockitoBean y @WebMvcTest
- `@MockBean` → `@MockitoBean` (`org.springframework.test.context.bean.override.mockito.MockitoBean`)
- `@WebMvcTest` → `org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest`
- `DaoAuthenticationProvider` → constructor `(UserDetailsService)` + `setPasswordEncoder(...)` (Spring Security 7.x)

## Cómo arrancar el backend en modo dev para probar auth manualmente
```bash
# 1. Asegúrate de tener .env con las variables (incluye RENTALS_JWT_SECRET y RENTALS_BOOTSTRAP_ADMIN_*)
# 2. Levanta PostgreSQL local:
docker compose up -d

# 3. Arranca el backend con perfil dev:
cd backend
SPRING_PROFILES_ACTIVE=dev ./gradlew bootRun

# 4. Login como ADMIN dev (no bootstrap; usa la semilla V1001):
curl -c cookies.txt -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin-dev-2024"}'

# 5. O login como arrendatario:
curl -c cookies.txt -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"ana.garcia","password":"dev-password-123"}'

# Nota: el admin de bootstrap (RENTALS_BOOTSTRAP_ADMIN_*) también se crea si no existe ningún ADMIN.
# En dev ambos mecanismos conviven: la semilla V1001 crea 'admin', el bootstrap no hace nada si ya existe.
# Para forzar el bootstrap, elimina el usuario 'admin' de la BD antes de arrancar.
```

## Problemas conocidos / riesgos
- **Sin bloqueo por intentos fallidos:** Ver D-1. El WAF de AWS (rate-based rule en /api/auth/login) es la mitigación recomendada para producción.
- **app_user.password_hash length=100:** La arquitectura especifica VARCHAR(100), pero DelegatingPasswordEncoder produce strings de ~68 chars ({bcrypt}$2a$10$... = 7+60=67). Hay margen. Si se añaden encoders con prefijos más largos en el futuro, revisar.
- **Jackson 3.x:** Los DTOs de la API (LoginRequest, AuthResponse, ChangePasswordRequest) son records Java. Jackson 3.x los serializa/deserializa correctamente. Los tests que necesiten serialización JSON deben usar `tools.jackson.databind.ObjectMapper`, no `com.fasterxml`.
- **Test de integración completo (B-04):** El build actual usa `@WebMvcTest` (sin BD real). Un test `@SpringBootTest` + Flyway + Testcontainers validaría el flujo completo login→acceso a endpoint. Recomendado en B-04.
