## Decisiones tomadas y por qué

### Patrón de test @WebMvcTest con seguridad (CRÍTICO para futuros tests)
En Spring Boot 4.x, `WebMvcTypeExcludeFilter.KNOWN_INCLUDES` excluye `@Configuration` classes que no sean `@Controller`, `@ControllerAdvice`, etc. Esto significa que **`SecurityConfig` y `JwtConfig` NO son cargados** por el slice de `@WebMvcTest`. Sin `SecurityConfig` no hay `@EnableWebSecurity`, no hay `HttpSecurity`, y `OAuth2ResourceServerWebSecurityAutoConfiguration.jwtSecurityFilterChain(HttpSecurity)` falla con `NoSuchBeanDefinition`.

**Solución comprobada:** Cada `@WebMvcTest` que necesite seguridad activa incluye un inner class `@TestConfiguration @EnableWebSecurity` que define:
```java
@Bean
SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/<relevant-paths>/**").hasRole("<ROLE>")
            .anyRequest().denyAll()
        );
    return http.build();
}
```
Y en el test class: `@MockitoBean JwtDecoder jwtDecoder`.

**Por qué funciona:** El `@TestConfiguration` inner class es registrado como component class ANTES de que los auto-configuraciones del `ImportsContextCustomizer` evalúen sus condiciones. Al haber un `SecurityFilterChain` bean definition, `@ConditionalOnDefaultWebSecurity` → FALSE → `OAuth2ResourceServerWebSecurityAutoConfiguration` es saltado. La única cadena activa es la del test.

### @AuthenticationPrincipal Jwt en tests (Spring Security 7.x)
El `jwt()` post-processor del `SecurityMockMvcRequestPostProcessors` usa `Jwt.Builder`. En Spring Security 7.x, el builder requiere `tokenValue` no vacío. Al usar `.jwt(j -> j.claim("tenantId", 1L))` sin un `tokenValue` explícito, el build falla con `"tokenValue cannot be empty"`. **Fix:** `.jwt(j -> j.tokenValue("test-token").claim("tenantId", 1L))`.

### DTOs en `web/dto/` (no `service/dto/`)
ARCHITECTURE §3 es la fuente de verdad. La nota de la tarea mencionaba `service/dto/` pero la arquitectura especifica `web/dto/`. Se siguió la arquitectura.
